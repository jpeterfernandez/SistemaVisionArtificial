CAMBIOS - 13/10/2026
Objetivo
Mejorar la fluidez del video en vivo y aumentar en un hilo el paralelismo CPU
de YOLO, conservando la resolución y los umbrales actuales de detección.

Cambios realizados
- La captura de cada stream ahora lee frames en un hilo de fondo y conserva
  solo el más reciente. Los frames antiguos se descartan mientras YOLO procesa,
  evitando que la transmisión acumule retraso.
- PyTorch suma un hilo intra-op al valor predeterminado al ejecutar YOLO en CPU.
  El incremento respeta el número de CPUs disponibles y se puede ajustar con
  YOLO_CPU_EXTRA_THREADS. No se cambia este ajuste cuando YOLO usa GPU.
- El stream en vivo usa YOLO_STREAM_IMG_SIZE=416 en lugar de 640. Este valor es
  configurable y solo afecta video; las inferencias de imágenes conservan 640.
- Se agregó una prueba para verificar que el lector conserva y entrega el frame
  más reciente.

Por qué
Antes, el mismo ciclo leía un frame, esperaba a que terminara YOLO y recién
entonces leía el siguiente. Separar la captura permite mantener al día el frame
que se muestra; el hilo CPU adicional permite a PyTorch paralelizar más trabajo.
La comparación local con best.pt dio una mediana aproximada de 823 ms a 640 y
453 ms a 416. Se eligió 416 como balance entre velocidad y detalle; bajar más
puede perder objetos pequeños. El hilo adicional se conservó como ajuste
solicitado, aunque la medición local de 4 frente a 5 hilos no mostró aceleración.
La mejora final depende del hardware, de la cámara y del costo de inferencia.

CAMBIOS - 13/10/2026

Objetivo
Permitir escoger dónde procesa YOLO según el hardware disponible, con controles
experimentales visibles y utilizables únicamente en el ambiente de desarrollo.

Cambios realizados
- El modo automático detecta CUDA y selecciona GPU solo si encuentra al menos
  1 GB de memoria libre; si no, usa CPU. La opción GPU manual se rechaza cuando
  PyTorch no dispone de CUDA.
- La configuración controla hilos CPU, límite de memoria GPU y tamaño del
  stream. Cambiar el perfil recarga el modelo bajo un bloqueo de inferencia.
- Si el modelo no puede cargarse con el perfil nuevo, se restaura el perfil y
  modelo anteriores para que YOLO siga disponible.
- El perfil se guarda en la base de datos y se vuelve a aplicar al arrancar el
  backend en desarrollo. En otros ambientes, el endpoint lo deshabilita.
- Configuración muestra hardware detectado, el dispositivo activo, los controles
  experimentales y una advertencia sobre la pausa breve al recargar YOLO.
- Se agregaron pruebas para la selección automática y el bloqueo de producción.

Por qué
YOLO recibe explícitamente el dispositivo de inferencia y el modelo se carga al
iniciar; editar una preferencia sin actualizar el modelo no cambiaría el lugar
real del procesamiento. El perfil aplica la configuración al modelo, limita los
recursos disponibles y protege el cambio con un bloqueo para no competir con
inferencias activas. La selección automática prioriza CUDA compatible con memoria
suficiente y conserva CPU como alternativa.

Objetivo
Aplicar las mejoras de operación solicitadas, con permisos por rol y zona para
usuarios, órdenes, cámaras, eventos y detecciones, y exportación de registros.
Odoo y las métricas de latencia/conectividad quedan fuera del alcance de esta
fase, según lo solicitado.

Cambios realizados
- Se agregaron allowed_zones a usuarios y zone a órdenes. ADMIN tiene alcance
  global; OPERATOR y VIEWER quedan limitados a las zonas asignadas. Las cuentas
  existentes migran con lista vacía para no otorgar acceso automáticamente.

  otra zona se rechaza.
- Eventos y detecciones conservan un snapshot de su zona. Cambiar una cámara de
  zona no cambia el alcance de sus registros históricos.
- Usuarios permite asignar zonas, roles, activar/desactivar y restablecer
  contraseñas; se conserva la protección del último administrador activo.
- La navegación y acciones visibles reflejan roles: configuración, usuarios y
  auditoría solo para ADMIN; VIEWER no puede iniciar inferencias ni acciones de
  escritura.
- Eventos, órdenes, detecciones y auditoría se pueden exportar a CSV con acceso
  y filtros por zona aplicados en servidor.
- Se agregó historial de auditoría y migraciones Alembic para auditoría, zonas
  y snapshots de registros.
- Se corrigió la prueba de órdenes para que no dependa de cámaras sembradas
  fuera de la suite.
